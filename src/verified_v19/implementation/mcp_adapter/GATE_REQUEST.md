# MCP adapter remote gate request

Run only on `benchmark-host` under the shared compilation/experiment lock.

1. Create an isolated environment and install the exact
   `requirements.txt`; retain every downloaded wheel/sdist hash and the fully
   resolved package list in a retained lock file, then pass that exact file to
   `gate.py --lock-file`.
2. Preserve Python version, source SHA-256 manifest and the three input case
   manifests. The cases must be generated by three distinct real private owner
   witnesses under one shared snapshot/terminal/public request, not by copying
   one proof and changing an audit label.
3. Run syntax/import checks, then start the existing HTTP service with real
   proof and terminal verification and all three owners admitted under the
   shared header.
4. Run `gate.py` with exactly three `--case LABEL=PATH` arguments and retain
   stdout, stderr, wall time, RSS and trace JSON.
5. Require negotiated protocol `2025-11-25`, SDK `mcp==1.29.1`, one listed
   `read_resource` tool with the exact six required inputs, and actual SDK
   calls for `initialize`, `tools/list` and every `tools/call`. Pass a fresh
   artifact path prefix with `--wire-log-prefix`; retain both raw JSONL files
   and require their SHA-256 values to match the trace.
6. Require three successful owner paths, distinct audit commitments and
   witness-source digests, a common terminal/public request apart from nonce,
   local resource/terminal/nonce mismatch rejection, HTTP body-binding
   rejection before nonce consumption, and HTTP `nonce-replay` on the repeated
   valid call.
7. Keep `synthetic_authorization_profile=true`,
   `production_oauth_compatible=false`, and
   `mcp_2026_07_28_compatible=false`. Do not report this gate as production
   OAuth interoperability or as a current-protocol MCP deployment.
